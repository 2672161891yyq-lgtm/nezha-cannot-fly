# 《哪吒不会飞》技术设计文档（TDD）

- 文档版本：V1.0
- 引擎：Cocos Creator 3.x
- 语言：TypeScript
- 平台：微信小游戏

## 1. 技术目标

- 模块边界清晰，玩法参数可配置。
- 障碍循环使用对象池，避免运行中频繁创建和销毁节点。
- 核心玩法不依赖微信接口，可在编辑器中完整调试。
- 平台能力统一通过适配层调用。
- 第一版保持轻量，不为尚未确定的功能提前搭建复杂框架。

## 2. 设计分辨率与适配

- 设计分辨率：750 × 1334，竖屏。
- 背景负责铺满屏幕，必要时允许边缘裁切。
- 玩法安全区域根据实际可见高度计算，不直接使用设备物理像素。
- UI 避开刘海、圆角和微信系统按钮区域。
- 玩家、通道和碰撞规则以设计空间单位计算，避免不同分辨率改变难度。

## 3. 场景规划

V1 使用两个场景：

### Boot.scene

- 初始化全局配置。
- 加载首屏必要资源。
- 初始化本地存档、音频和平台适配层。
- 完成后进入 MainGame.scene。

### MainGame.scene

- 背景视差层。
- 障碍容器。
- 玩家节点。
- 特效容器。
- 游戏 UI。
- 暂停与结算弹层。

使用一个主游戏场景可减少切场景等待，重新开始时只重置运行状态，不重复加载全部资源。

## 5. 核心模块

### GameDirector

- 管理 Boot、Ready、Playing、Paused、GameOver 状态。
- 负责开始、暂停、恢复、结束和重开流程。
- 只有该模块可以切换游戏状态，避免各组件互相修改状态。

### InputController

- 监听触摸或鼠标输入。
- 过滤 UI 点击。
- 将输入转换为 `flap`、`pause` 等游戏指令。
- 不直接操作玩家节点。

### PlayerController

- 保存竖直速度。
- 执行自定义重力、上升冲量和最大下落速度。
- 根据速度切换姿态、动画和风火轮效果。
- 固定水平位置，只改变竖直位置和旋转。

### ObstacleSpawner

- 根据配置生成合法通道。
- 从对象池获取一组上下障碍。
- 选择上下障碍类型、视觉尺寸和通道中心。
- 记录上一次通道，执行高度差和重复组合限制。

### ScrollSystem

- 统一推动障碍、地面和视差背景向左移动。
- 游戏暂停或结束时停止玩法滚动。
- 将离开屏幕的障碍组归还对象池。

### CollisionSystem

- 接收玩家与障碍、边界的碰撞事件。
- 接收玩家穿过计分触发区的事件。
- 做一次性结算保护，防止同一帧重复触发失败。

### ScoreSystem

- 当前分数。
- 同组障碍只计分一次。
- 计算并保存最高分。
- 通知 UI、音效和得分特效。

### PoolManager

- 预创建障碍组和常用特效。
- 统一获取、回收和重置对象。
- 回收时清除动画、计分标记和临时状态。

### AudioService

- 管理背景音乐、音效和静音状态。
- 对高频音效做并发限制。
- 从本地存档恢复声音设置。

### SaveService

- 保存最高分、声音设置和文档版本号。
- V1 使用本地存储，不依赖登录和网络。
- 读取失败时回退到默认值，不阻断游戏。

### PlatformAdapter

- 封装微信与编辑器环境差异。
- V1 仅提供初始化、生命周期、存储和安全区相关能力。
- 游戏逻辑禁止直接散落调用 `wx.*`。

## 6. 运行时结构

```text
GameDirector
├── InputController ──> PlayerController
├── ObstacleSpawner ──> PoolManager
├── ScrollSystem
├── CollisionSystem ──> ScoreSystem
├── AudioService
├── SaveService
└── UIController
```

模块通过事件或明确接口通信。禁止使用大量无类型的全局事件；事件名称、载荷和触发时机应集中定义。

## 7. 运动方案

V1 使用自定义竖直运动，不将手感完全交给物理引擎：

```text
velocityY += gravity * deltaTime
velocityY = clamp(velocityY, maxFallSpeed, maxRiseSpeed)
positionY += velocityY * deltaTime
```

点击时直接将 `velocityY` 设置为配置中的上升速度，以获得稳定、可预测的连续点击手感。

碰撞使用 Cocos 2D Collider。角色碰撞体应由少量圆形或胶囊形近似组成，不使用贴图轮廓生成的复杂多边形。

## 8. 障碍预制体结构

```text
ObstaclePair
├── TopAnchor
│   └── TopVisual
├── BottomAnchor
│   └── BottomVisual
├── ScoreTrigger
└── DebugView
```

- `TopVisual` 与 `BottomVisual` 可替换为不同障碍预制体。
- 八卦阵旋转等纯视觉动画只作用于视觉子节点，不改变根碰撞体。
- 火球视觉节点与圆形碰撞中心共用同一个正弦位移快照；雷电碰撞只在固定时间轴的生效阶段启用。
- 动态位移上限必须在生成安全通道时预留，动画不得临时缩小已生成的合法通道。
- `ScoreTrigger` 是竖向触发区域，位于障碍组穿越线。
- `DebugView` 仅在开发模式显示通道边界、碰撞体和安全区。

## 9. 数据配置

配置分为三类：

- `GameConfig`：重力、上升速度、滚动速度、玩家位置、边界。
- `DifficultyConfig`：按分数区间定义通道高度、速度和高度变化上限。
- `ObstacleConfig`：障碍类型、权重、视觉尺寸范围、碰撞体模板。

代码内提供默认值；外部 JSON 读取失败时使用默认值。正式发布前，配置需要通过构建校验，避免字段缺失或非法范围。

## 10. 随机与公平性

障碍生成使用可注入随机种子，便于复现问题。每次生成必须经过以下校验：

1. 通道完整处于玩法安全区域。
2. 通道高度不低于当前难度下限。
3. 与上一组通道中心高度差不超过允许值。
4. 上下障碍视觉不侵入安全通道。
5. 当前组合未达到连续重复上限。

若随机结果连续多次不合法，直接使用安全回退组合，不能无限重试。

## 11. 性能预算

- 目标：主流设备 60 FPS；低端目标设备不得持续低于 30 FPS。
- 玩法中不频繁实例化或销毁障碍、分数特效和火星粒子。
- 同屏活动障碍组建议不超过 4 组。
- 粒子数量设硬上限，暂停和离屏时停止更新。
- 单张纹理建议不超过 2048 × 2048；合理使用图集和平台纹理压缩。
- 避免每帧创建临时数组、字符串和对象。
- 背景视差使用少量循环节点，不使用超长背景图。

## 12. 日志与调试

开发版本提供：

- 当前 FPS。
- 玩家位置、速度和碰撞体显示。
- 障碍通道高度、中心、速度和随机种子。
- 当前游戏状态。
- 一键固定随机种子并复现上一局。

发布构建关闭调试视图和高频日志。

## 13. 测试重点

- 首次点击是否只触发一次起飞。
- 快速连续点击时速度是否超限。
- 前后台切换是否自动暂停。
- 暂停后物理、动画、音效是否一致冻结或恢复。
- 重开 50 次是否出现残留障碍、重复计分或内存持续增长。
- 极窄和极高屏幕比例下，通道是否仍在可见安全区域。
- 低帧率下是否发生穿透障碍。
- 同一随机种子是否能复现相同障碍序列。
