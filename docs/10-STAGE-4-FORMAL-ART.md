## 2. 资源结构

正式运行资源迁移至 Cocos Creator 的 `resources` 目录，通过稳定路径异步预加载：

```text
assets/resources/art/
├── backgrounds/day/        # 五层陈塘关背景
├── branding/               # 标题与应用图标
├── characters/nezha/       # 哪吒与风火轮状态
├── effects/                # 得分、碰撞、火星、飘叶
├── obstacles/ground/       # 山峰、石柱、火球
├── obstacles/sky/          # 乌云、雷电、八卦阵
└── ui/                     # 分数牌、结算面板与通用组件
```

迁移保留了原 PNG 和 `.meta` UUID；高清生成母图继续保存在 `art-source/generated/`，不会被运行时直接打包引用。

## 3. 画面与动画规则

### 背景

- 天空层固定，保证画面稳定。
- 远云、远景、陈塘关和前景依距离增加轻微横向摆动，形成柔和视差。
- 前景飘叶使用独立低频动画，位于玩法层之后，不参与碰撞。
- 背景始终按 750 × 1334 设计画布等比适配。

### 哪吒与风火轮

- Ready 与巡航使用 `nezha_idle`。
- 点击上升使用 `nezha_boost`，自然下坠使用 `nezha_fall`。
- 碰撞后先显示 `nezha_hit`，0.55 秒后切换 `nezha_result`。
- 风火轮根据飞行状态切换常态、加速和弱火图，并保留反向旋转与火焰强度变化。
- 哪吒发带、风火轮火焰和火星不进入半径 43 的玩家碰撞圆。

### 障碍与公平性

- 六种障碍继续使用阶段 2 的同一对象池和组合生成器。
- 正式 Sprite 只替换显示节点；碰撞仍由经过验证的矩形或圆形数学判定负责。
- 火球 Sprite 与圆形碰撞共享同一正弦位移。
- 雷电通过亮度、透明度和文字区分预警、生效与冷却。
- 上方乌云与雷电按“画面顶边—通道上边缘”完整铺设；八卦阵通过云层连接到顶边。
- 竖屏适配统一使用固定高度策略；390×844、430×932 等长屏不再在画面上下留下额外区域。
- 上方障碍增加 72 设计像素的顶边溢出量，用于抵消透明 PNG 留白并保证可见像素贴边。
- 雷电只使用亮度和文字提示状态，不再整体缩放，避免视觉边缘偏离碰撞边缘。
- 八卦阵使用两层正式 Sprite 反向旋转，碰撞圆保持固定。

## 4. 代码职责

- `FormalArtConfig.ts`：28 项运行时素材路径、五层视差配置、角色与障碍映射、画面配色。
- `FormalArtLoader.ts`：异步加载并校验全部 SpriteFrame。
- `GrayboxGame.ts`：正式 Sprite、状态切换、五层背景、VFX、UI 与灰盒失败回退。
- `tools/tests/stage4-formal-art.test.ts`：素材键、路径、背景层、六类障碍和状态映射检查。

场景仍保留 `GrayboxGame` 组件名，以保持 `Boot.scene` 已序列化组件 UUID 稳定；组件内部已经切换为正式素材运行时。
