# 《哪吒不会飞》V1 开发计划与验收标准

- 文档版本：V1.1
- 交付目标：可提交微信开发者工具体验版的完整核心游戏

## 1. 交付阶段

### 1.1 总体排期

以下时间按单人全职开发估算，不包含等待外部音频、美术返修或微信审核的时间。

| 阶段 | 主要工作 | 交付结果 | 预计时间 | 累计时间 |
|---|---|---|---:|---:|
| 0. 工程基线 | 锁定工具版本、设计分辨率、目录与代码规范 | 可运行的微信小游戏空工程 | 0.5～1 天 | 0.5～1 天 |
| 1. 核心玩法灰盒 | 点击上升、无输入下落、速度限制、倾斜、边界、碰撞、重开 | 可连续试玩的灰盒版本 | 2～3 天 | 2.5～4 天 |
| 2. 障碍系统 | 对象池、随机生成、安全通道、9 种组合、计分线、难度曲线 | 完整无尽玩法 | 2～3 天 | 4.5～7 天 |
| 3. 动态表现与公平性 | 火球浮动、雷电预警、八卦阵旋转、风火轮状态 | 静态与动态障碍均可公平游玩 | 1～2 天 | 5.5～9 天 |
| 4. 正式素材接入 | 陈塘关多层背景、哪吒状态、障碍、VFX、UI、屏幕适配 | 接近目标画面的美术版本 | 2～3 天 | 7.5～12 天 |
| 5. 游戏流程 | 首页、首次教学、暂停、结算、最高分、重新起飞 | 完整单局闭环 | 1～2 天 | 8.5～14 天 |
| 6. 音频与手感 | 点火、得分、碰撞、雷电、火球、震屏和命中停顿 | 反馈完整的候选版本 | 1～2 天 | 9.5～16 天 |
| 7. 微信真机验收 | 包体、内存、帧率、触摸中断、前后台、屏幕与低端机测试 | 第一版发布候选包 | 2～3 天 | 11.5～19 天 |

第一版顺序开发总工期预计为 **11.5～19 个工作日**，约 3～4 周。每个阶段通过验收后才进入下一阶段。

### 1.2 阶段 0：工程基线

交付内容：

- 创建并锁定 Cocos Creator 与微信开发者工具具体版本。
- 配置 TypeScript、竖屏和 750 × 1334 设计分辨率。
- 建立目录、场景、基础配置和代码规范。
- 编辑器预览与微信开发者工具构建成功。

通过条件：空场景可以在编辑器和微信开发者工具正常运行，无启动报错。

预计时间：0.5～1 天。

### 1.3 阶段 1：核心玩法灰盒

状态：**已完成并通过验收（2026-10-10）**。详细记录见 `07-STAGE-1-GRAYBOX.md`。

交付内容：

- 临时方块角色。
- 点击获得固定上升速度，无输入时受重力下坠。
- 上升和下坠速度限制、角色倾斜、上下边界。
- 一组固定灰盒障碍、基础滚动、碰撞和得分。
- Ready、Playing、GameOver 与快速重新开始。

通过条件：使用临时素材可以连续试玩；点击、下坠、碰撞和重开稳定；重力、上升速度与滚动速度均可配置。

预计时间：2～3 天。

说明：本作保持 Flappy Bird 式“点击上升”，不采用参考图中的“长按上升”。长按控制属于另一套手感，会改变当前 GDD 的核心玩法。

### 1.4 阶段 2：障碍系统

状态：已完成并通过技术验收，详见《[阶段 2：障碍系统](08-STAGE-2-OBSTACLE-SYSTEM.md)》。阶段 3 动态表现已经接入，20 局主观手感验收现等待微信目标设备复测。

交付内容：

- 障碍组对象池与屏幕外回收。
- 上方三类、下方三类，共九种随机组合。
- 安全通道、通道中心范围和相邻高度差限制。
- 重复组合限制、固定随机种子和安全回退组合。
- 计分线、一次性计分保护与难度曲线。

通过条件：连续自动生成 10,000 组障碍无非法通道；人工连续游玩 20 局无明显无解组合；对象复用不重复计分。

预计时间：2～3 天。

### 1.5 阶段 3：动态表现与公平性

状态：**已完成并通过技术与网页运行验收（2026-10-10）**。详细记录见《[阶段 3：动态障碍](09-STAGE-3-DYNAMIC-OBSTACLES.md)》。20 局微信真机主观公平性验收仍需在目标设备上完成。

交付内容：

- 火球做小幅、可预测的正弦浮动，视觉与碰撞体同步移动。
- 雷电先预警再进入有效碰撞阶段，预警与生效时间固定。
- 八卦阵视觉旋转，继续使用稳定圆形碰撞体。
- 风火轮根据待机、上升和下坠状态切换旋转与火焰表现。
- 障碍生成时将动态位移的最大范围计入安全通道计算。

通过条件：动态障碍不存在无预警伤害；移动范围不会使合法通道变成无解通道；关闭动画后碰撞逻辑仍可被调试和复现。

预计时间：1～2 天。

### 1.6 阶段 4：正式素材接入

状态：**已完成并通过技术与网页视觉验收（2026-10-10）**。详细记录见《[阶段 4：正式素材接入](10-STAGE-4-FORMAL-ART.md)》。微信目标设备上的主观可读性与性能复测保留到阶段 7。

交付内容：

- 接入陈塘关五层视差背景。
- 接入哪吒待机、上升、下坠、受击和结算状态。
- 接入六类障碍、风火轮、得分、碰撞和环境特效。
- 接入正式首页、游戏中、暂停和结算 UI。
- 完成素材锚点、缩放、碰撞体、图集和屏幕比例适配。

通过条件：正式素材不破坏已经验证的碰撞和通道规则；不同屏幕比例下角色、通道和 UI 均完整可见；背景装饰不造成障碍误判。

预计时间：2～3 天。

说明：参考图中的“天宫多层背景”和“八戒状态动画”与本项目不符，已修正为“陈塘关多层背景”和“哪吒状态动画”。

### 1.7 阶段 5：游戏流程

交付内容：

- 首页与“点击起飞”首次教学。
- Ready、Playing、Paused、GameOver 完整状态流转。
- 暂停、继续、结算和重新起飞。
- 本局分数、最高分和新纪录提示。
- 本地最高分与声音设置存档。

通过条件：首页到单局游戏、暂停、结算和重开形成完整闭环；UI 点击不会误触发飞行动作；最高分重启后仍正确保存。

预计时间：1～2 天。

### 1.8 阶段 6：音频与操作手感

交付内容：

- 风火轮点火、上升、得分、碰撞、雷电、火球和 UI 音效。
- 背景音乐与环境音循环。
- 得分、受击、雷电的轻量震屏或振动反馈。
- 受击瞬间短暂停顿，增强碰撞反馈。
- 高频点击下的音效并发限制。

通过条件：所有关键操作均有明确但不过量的反馈；音效开关正确保存；连续点击不爆音；震屏和停顿不影响碰撞公平性。

预计时间：1～2 天。

### 1.9 阶段 7：微信真机验收

交付内容：

- 微信小游戏构建与体验版上传。
- 包体、纹理、图集、对象池、粒子和内存优化。
- 帧率、长时间运行和连续重开测试。
- 触摸中断、来电或系统打断、前后台切换测试。
- 刘海屏、圆角屏、长短屏和至少一台低端机测试。
- 阻断级与严重级缺陷清零。

通过条件：完成本文全部功能、体验和性能验收项；生成可以在微信真机中稳定游玩的第一版发布候选包。

预计时间：2～3 天。

## 2. 阶段验收闸门

### 闸门 A：最小可玩原型

包含阶段 0～1，预计累计 2.5～4 天。

老板验收重点：点击飞行是否舒服、下坠是否自然、失败后是否愿意立即重开。未通过时只调整手感，不继续扩展障碍和美术。

### 闸门 B：完整无尽玩法

包含阶段 2～3，预计新增 3～5 天，累计 5.5～9 天。

老板验收重点：九种组合是否有变化、动态障碍是否公平、难度增长是否合理。

### 闸门 C：内容完整候选版

包含阶段 4～6，预计新增 4～7 天，累计 9.5～16 天。

老板验收重点：正式画面是否符合方向、单局流程是否顺畅、音画反馈是否完整。

### 闸门 D：微信发布候选包

包含阶段 7，预计新增 2～3 天，最终累计 11.5～19 天。

老板验收重点：真机稳定性、屏幕适配、包体和低端机表现。

## 3. 功能验收清单

### 启动与状态

- [x] 首次启动无报错、无黑屏。（网页构建已验证，微信目标构建成功。）
- [ ] Ready 状态下障碍不移动、角色不下坠。
- [ ] 首次点击同时开始游戏并触发一次上升。
- [ ] 暂停后计时、移动、计分和输入全部停止。
- [ ] 微信切到后台时自动暂停。
- [ ] GameOver 只触发一次。
- [ ] 重新开始无需重新加载完整场景资源。

### 玩家

- [ ] 单击、连击和间歇点击响应稳定。
- [ ] 不操作时下坠曲线自然。
- [ ] 角色不会因连续点击突破最大速度。
- [ ] 角色姿态与当前竖直速度一致。
- [x] 发带、火焰和拖尾保持为纯视觉节点，不进入玩家碰撞圆。

### 障碍

- [x] 六类障碍都可以正常生成和回收。
- [x] 九种上下组合均可出现。
- [x] 同一组合不会连续出现三次。
- [x] 通道不会超出玩法安全区域。
- [x] 相邻通道不存在不可调整的高度跳变。
- [x] 八卦阵等纯视觉动画不改变碰撞体；火球视觉与圆形碰撞按规则同步移动；雷电只在预告后的生效期启用碰撞。
- [x] 对象池复用后类型、动画时间轴和计分状态均正确重置。

### 分数与存档

- [x] 每组障碍只增加一次分数。
- [x] 碰撞与计分同帧时不错误加分。
- [ ] 最高分刷新正确。
- [ ] 关闭并重新进入游戏后最高分仍存在。
- [ ] 存档损坏或缺失时可以使用默认值进入游戏。

### UI 与音频

- [x] 分数在 390×844、430×932 和 360×640 竖屏比例下完整可见。
- [ ] 暂停按钮不与微信系统区域冲突。
- [ ] UI 点击不会同时触发起飞。
- [ ] 静音设置重启后保持。
- [ ] 高频点击不会导致音效爆音或过量叠加。

## 4. 体验验收

- [ ] 新玩家只看一次“点击起飞”即可理解操作。
- [ ] 前三组障碍明显宽容。
- [ ] 失败原因能够从画面中立即判断。
- [ ] 玩家不会把背景建筑、雨滴、火星或光晕误认成碰撞物。
- [ ] 失败到再次开始的操作不超过两次点击。
- [ ] 首局体验中能明确感受到风火轮与哪吒的喜剧性格。

## 5. 性能验收

- [ ] 目标主流设备稳定接近 60 FPS。
- [ ] 低端测试设备不持续低于 30 FPS。
- [ ] 连续运行 20 分钟无明显内存持续上涨。
- [ ] 连续重新开始 50 次无节点、监听器或音效实例泄漏。
- [ ] 同屏粒子和障碍数量始终在预算内。
- [ ] 微信小游戏包体符合提交要求；超出主包预算时再规划分包。

## 6. 缺陷等级

| 等级 | 定义 | 发布要求 |
|---|---|---|
| 阻断 | 无法启动、无法游戏、必现卡死、存档阻断 | 必须清零 |
| 严重 | 错误碰撞、重复计分、无解关卡、明显掉帧 | 必须清零 |
| 一般 | 局部动画、适配、音效或轻微视觉问题 | 评估后修复 |
| 轻微 | 不影响理解和操作的细节问题 | 可进入后续版本 |

## 7. 发布前最终确认

- [ ] Cocos Creator、微信基础库和构建参数已记录并锁定。
- [ ] 所有美术、字体、音乐和音效拥有明确可用授权。
- [ ] 未使用现有影视或动画版本的哪吒造型。
- [ ] 隐私与权限声明和实际调用一致。
- [ ] 体验版二维码完成至少两台不同档位真机测试。
- [ ] 保存最终数值配置、构建包和版本记录。

## 8. V1 完成定义

当阶段 0～7 和闸门 A～D 全部通过、阻断与严重缺陷清零，并生成可在微信中实际游玩的体验版时，V1 才算完成。仅在编辑器内可运行不视为完成。
